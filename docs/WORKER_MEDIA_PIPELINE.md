# Worker media pipeline

Image bytes do not travel inside job JSON in either direction.

Input references are frozen once at the API edge:

```
data URL / remote URL
→ download once + PNG/JPEG/WebP magic/dimensions/hash
→ MediaStore
→ Job { stable url, asset_id, sha256, mime, bytes, width, height }
```

The worker then reads the immutable stored URL. Mutable remote URLs and original
base64 are not persisted in Job/Redis/Postgres.

Generated bytes leave the worker through `POST /api/worker/media`:

```
Provider download
→ magic (PNG/JPEG/WebP)
→ POST /api/worker/media
   (worker token + job_id + attempt_id + lease_id + fencing_token)
→ MediaStore
→ asset_id + stable url
→ /api/worker/result { url, resultAssets, resultConfidences }
```

Stale fencing tokens are 409 `STALE_LEASE`. An old worker cannot write into a new attempt.

Job / Redis / result body store:

- `asset_id`
- `url`
- `sha256`
- `mime`
- `bytes`
- `width` / `height`

They do not store the image payload. Gateway validation recalculates and checks
worker metadata before terminal success. `response_format=b64_json` reads the
asset only at the final API edge.

Metrics: `worker_media_upload_ms`, `media_store_ms`.

Live 15MB soak: **NOT_EXECUTED**. Unit covers 1MB / 5MB / 15MB store put.
